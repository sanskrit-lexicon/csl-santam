# csl-santam — Roadmap 2026–2027

_Created: 03-07-2026 · Last updated: 03-07-2026_

Where [sanskrit-lexicon/csl-santam](https://github.com/sanskrit-lexicon/csl-santam) goes next, and — as important — where it deliberately does **not** go. Authored from an evidence-based audit plus four rulings by the maintainer (recorded verbatim in [Decisions taken](#decisions-taken)). Future sessions should execute from the waves below; the wave-1 work has an executable handoff ([H111](https://github.com/gasyoun/Uprava/blob/main/handoffs/H111_csl_santam_wave1.md)).

---

## Where we are (July 2026)

csl-santam is a web-frontend port of the Cologne ["MWScan tamil"](http://www.sanskrit-lexicon.uni-koeln.de/scans/MWScan/tamil/index.html) multi-dictionary search: a single form ([php/index.html](https://github.com/sanskrit-lexicon/csl-santam/blob/master/php/index.html)) POSTs to one backend ([php/recherche.php](https://github.com/sanskrit-lexicon/csl-santam/blob/master/php/recherche.php)), which queries **one combined SQLite table** `tamil(id, st, en)` spanning four lexica. Maintainer of record: Thomas Malten (th.malten@uni-koeln.de), Cologne. Default branch: `master`.

| id | code | Lexicon | Entries | Status |
|----|------|---------|--------:|--------|
| 1 | `mwd` | Monier-Williams (Cologne Digital Sanskrit Lexicon) | 166,434 | active (default) |
| 2 | `cap` | Capeller's Sanskrit–English Dictionary | 37,413 | active |
| 3 | `otl` | Cologne Online Tamil Lexicon | 117,773 | active |
| 4 | `cpd` | Concise Pahlavi Dictionary | 4,218 | **disabled** (option commented out; excluded from `all` via `id<4`) |

**The unique asset:** csl-santam is the only repo in the ecosystem offering a *combined* search that includes the **Cologne Online Tamil Lexicon** and **Capeller** alongside Monier-Williams. That Tamil/Capeller breadth — not the aging PHP shell around it — is what is worth carrying forward.

**Recently advanced (2026-06-14):** four security fixes landed on `master` — reflected XSS ([PR #4](https://github.com/sanskrit-lexicon/csl-santam/pull/4)), SQLi via search term ([PR #5](https://github.com/sanskrit-lexicon/csl-santam/pull/5)), SQLi via `maxhits` ([PR #6](https://github.com/sanskrit-lexicon/csl-santam/pull/6)), regex-injection/ReDoS ([PR #7](https://github.com/sanskrit-lexicon/csl-santam/pull/7)) — plus a full docs set ([README.md](https://github.com/sanskrit-lexicon/csl-santam/blob/master/README.md), [docs/ARCHITECTURE.md](https://github.com/sanskrit-lexicon/csl-santam/blob/master/docs/ARCHITECTURE.md), [docs/USE_CASES.md](https://github.com/sanskrit-lexicon/csl-santam/blob/master/docs/USE_CASES.md), [CHANGELOG.md](https://github.com/sanskrit-lexicon/csl-santam/blob/master/CHANGELOG.md), [.ai_state.md](https://github.com/sanskrit-lexicon/csl-santam/blob/master/.ai_state.md)), [CLAUDE.md](https://github.com/sanskrit-lexicon/csl-santam/blob/master/CLAUDE.md), [CONTRIBUTING.md](https://github.com/sanskrit-lexicon/csl-santam/blob/master/CONTRIBUTING.md), CodeQL, and Dependabot + auto-merge.

**The gaps this roadmap closes:**

1. **Deployment is XAMPP-locked.** The app only runs under `C:\xampp` + Apache + PHP; it cannot live on GitHub Pages the way sibling [kosha](https://github.com/gasyoun/kosha) now does (kosha shipped a static-cache → Pages tier in release 0.5.0).
2. **The security work is unreleased** — `CHANGELOG.md` still carries an uncut `[Unreleased] — 2026-06-14`; the repo has **no tags at all**.
3. **Invisible to the hubs** — csl-santam has no row in [Uprava/GTD_NEXT_ACTIONS.md](https://github.com/gasyoun/Uprava/blob/main/GTD_NEXT_ACTIONS.md) or [Uprava/PROJECT_INTERLINKS.md](https://github.com/gasyoun/Uprava/blob/main/PROJECT_INTERLINKS.md), and **branch protection is off**.
4. **Input is HK-ASCII-only** — users must type Harvard-Kyoto romanization (no Devanagari/IAST), and case-folding silently conflates HK phonemes (`A`/`a`, `T`/`t`, `S`/`s`).
5. **Small queued tech-debt** — the "Pali"→"Pahlavi" comment mislabel, an unclamped `maxhits`, unescaped `%`/`_` in the `substring` LIKE branch, and a stale [readme_dev.txt](https://github.com/sanskrit-lexicon/csl-santam/blob/master/readme_dev.txt).

## Strategy in one line

Build the **static, backend-free version** of csl-santam not as a throwaway rewrite but as the **migration vehicle**: a normalized, server-less corpus + client-side search is simultaneously (a) the GitHub-Pages-hostable modern app that retires the XAMPP dependency and (b) exactly the artifact [kosha](https://github.com/gasyoun/kosha) can later absorb. Every wave moves the unique Tamil/Capeller/Pahlavi combined-search capability one step closer to a home that outlives the PHP shell.

## Wave 1 — Stabilize, release, register (no architecture change)

**Unblocked now.** Pure hygiene + the small queued fixes; ships the security work as a real release and makes the repo visible to the rest of the empire. Executable handoff: [H111](https://github.com/gasyoun/Uprava/blob/main/handoffs/H111_csl_santam_wave1.md).

- **Cut the first release `0.1.0`.** Promote `CHANGELOG.md`'s `[Unreleased] — 2026-06-14` to `0.1.0`, tag, and cut the GitHub release (via `/cut-release`). The four security fixes deserve a citable version; there are currently no tags.
- **Land the queued small fixes** (all in [php/recherche.php](https://github.com/sanskrit-lexicon/csl-santam/blob/master/php/recherche.php)): "Pali"→"Pahlavi" comment; default+clamp `maxhits` to `50`/`1000`; `ESCAPE`-clause the `%`/`_` metacharacters in the `substring` LIKE branch. Fold or retire the stale [readme_dev.txt](https://github.com/sanskrit-lexicon/csl-santam/blob/master/readme_dev.txt).
- **Baseline files:** add `CODE_OF_CONDUCT.md`, `SECURITY.md`, `.pre-commit-config.yaml` (scoped to a PHP/Perl repo — YAML/whitespace hooks). Turn **branch protection** on for `master`.
- **Hub registration:** add csl-santam rows to [Uprava/PROJECT_INTERLINKS.md](https://github.com/gasyoun/Uprava/blob/main/PROJECT_INTERLINKS.md) (as a corpus source feeding the eventual kosha fold) and a maintenance row + the wave-2 human actions to [Uprava/GTD_NEXT_ACTIONS.md](https://github.com/gasyoun/Uprava/blob/main/GTD_NEXT_ACTIONS.md).

**Exit:** tagged `0.1.0`, green pre-commit, protected `master`, visible in the hubs.

## Wave 2 — Usability + resolve the Pahlavi question (still PHP-hosted)

**Unblocked by Wave 1.** Improve the experience of the app *as it exists* while the static port is designed, and settle the two data questions.

- **Transliteration input (Deva/IAST → HK).** Add a **client-side** input helper so users can type Devanagari or IAST and have it transcoded to Harvard-Kyoto before the query is built. **Reuse an existing org transcoder** — check [SHARED_CODE.md](https://github.com/sanskrit-lexicon/SHARED_CODE.md) §transcoders and kosha's transliteration layer first; do **not** write transcoder #63. This is the single biggest usability lift and it is JS-only (no backend change), so it also seeds Wave 3's client-side app.
- **Case-sensitive HK toggle (optional, smaller).** Offer an opt-out from the lossy default so `A`/`a`, `T`/`t`, `S`/`s` stop conflating for power users. Document the current folding behavior either way.
- **Resolve the Pahlavi dictionary (id 4).** Per the ruling, **investigate before re-enabling**: the `<option value=cpd>` was already commented out in the 2022 PHP initial commit, so the reason predates our git visibility. Ask Thomas Malten / check the Perl origin why `cpd` was disabled (quality? rights? incompleteness?). Re-enable + include in `all` only if the reason is stale; otherwise leave disabled and document the rationale. → GTD `@WAITING` on Cologne.

**Exit:** users can type Devanagari/IAST; the Pahlavi status is a documented decision, not an accident.

## Wave 3 — Static, backend-free build on GitHub Pages (the ruling)

**The central ruling. Unblocked by Wave 2's client-side transliteration groundwork.** Rebuild search as a serverless client-side app so csl-santam runs on GitHub Pages with **zero backend**, ending the XAMPP dependency. The PHP + Perl backends stay in-repo as the legacy reference implementation.

- **Pick the client-side engine** (a genuine sub-fork for a `/decision-record`): **(a)** SQLite-WASM / `sql.js` shipping the existing `tamil.sqlite` and running the same SQL client-side, versus **(b)** a **kosha-style prebuilt static-cache tier** (kosha's P2 static-cache generator, see [kosha docs/README.md](https://github.com/gasyoun/kosha/blob/main/docs/README.md)) that pre-renders per-headword pages. Prior-art check kosha's P2 approach first — it already solved "Sanskrit dictionary search on Pages."
- **Normalize the corpus once** as the migration artifact: re-export [sqlite/ganz.txt](https://github.com/sanskrit-lexicon/csl-santam/blob/master/sqlite/ganz.txt) to clean UTF-8 (retiring the per-row `iconv("Windows-1252","UTF-8")` workaround — already flagged in the code), with explicit dictionary tags. This same normalized export is what Wave 4 hands to kosha.
- **Preserve search semantics** documented in [docs/USE_CASES.md](https://github.com/sanskrit-lexicon/csl-santam/blob/master/docs/USE_CASES.md): four match modes (exact/prefix/suffix/substring), `st` vs `en` reverse lookup, AND-joining, the `all` = mwd+cap+otl scope.
- **Publish** via GitHub Pages. Run `/publish-safety-check` first (rights on the four lexica, no bulk-leakage surprises). Coordinate visibility with Cologne per [kosha RELATIONS.md](https://github.com/gasyoun/kosha/blob/main/RELATIONS.md) §7 diplomacy triggers.

**Exit:** a live Pages URL serving the combined Sanskrit+Tamil+Capeller search with no server; the XAMPP-only limitation is gone.

## Wave 4 — Fold into kosha, then retire the standalone app (the ruling)

**The strategic ruling: eventual fold-into-kosha. Unblocked by Wave 3's normalized corpus.** Treat csl-santam as a *data source to be absorbed*, not a permanent product.

- **Feed the normalized 4-lexicon corpus into kosha's pipeline.** kosha does not currently cover the Cologne Tamil Lexicon or Capeller; this is where that breadth lands permanently. Register the feed in [Uprava/PROJECT_INTERLINKS.md](https://github.com/gasyoun/Uprava/blob/main/PROJECT_INTERLINKS.md). Needs kosha-side coordination (schema mapping HK↔kosha's transliteration model, provenance tagging).
- **Redirect / archive plan.** Once kosha serves the combined search, point csl-santam's Pages app at kosha (or freeze it as a citable snapshot) and move the repo to maintenance-only. Do **not** delete — preserve the Perl/PHP origin and the docs as historical record.
- **Diplomacy.** The fold touches kosha and Cologne upstream; run it through [kosha RELATIONS.md](https://github.com/gasyoun/kosha/blob/main/RELATIONS.md) before any public consolidation.

**Exit:** the unique Tamil/Capeller/Pahlavi capability lives in kosha; csl-santam is a documented, archived origin.

## Decisions taken

Rulings by the maintainer, 03-07-2026 (via `/roadmap-interview` `AskUserQuestion`):

1. **Deployment → static Pages port (client-side).** Rebuild search serverless (SQLite-WASM/`sql.js` or kosha-style static-cache) so it runs on GitHub Pages; PHP/Perl kept as legacy reference. _Rationale: ends the XAMPP lock and matches the org's kosha direction._ → Wave 3.
2. **Positioning → plan eventual fold-into-kosha.** Absorb the 4-lexicon corpus into kosha's pipeline over time, then retire the standalone app. _Rationale: consolidation; kosha is the modern successor and lacks Tamil/Capeller coverage._ → Wave 4.
3. **Pahlavi (id 4) → investigate why disabled first.** Re-enable only if the reason is stale; the disable predates our git visibility (2022 initial commit). _Rationale: avoid resurrecting something Cologne deliberately hid._ → Wave 2.
4. **Input UX → add transliteration input (Deva/IAST → HK).** Client-side helper reusing an existing org transcoder. _Rationale: HK-ASCII-only input is the biggest usability barrier._ → Wave 2.

## Non-goals (considered and ruled out — do not re-propose)

- **Docker-izing the PHP backend as an end state.** Considered for deployment; rejected in favor of the static Pages port (a container still needs a host and does not get free Pages hosting). A dev container purely to ease local PHP testing is fine, but it is not the deployment target.
- **Security-and-docs-only (leave deployment untouched).** Considered; rejected — the ruling is to modernize deployment, not freeze it.
- **Advancing csl-santam indefinitely as a distinct standalone product.** Considered; rejected in favor of eventual fold-into-kosha. New standalone features beyond Waves 1–3 should be weighed against "does this just move to kosha anyway?"
- **Blindly re-enabling the Pahlavi dictionary.** Rejected — investigate the disable reason first (Wave 2).
- **Adding a `/u` (UTF-8) flag to the `regexp` UDF, or "fixing" the byte-wise `lower()`.** These are **correct** for the current single-byte ASCII HK corpus (see [.ai_state.md](https://github.com/sanskrit-lexicon/csl-santam/blob/master/.ai_state.md) Dev Notes). They only become bugs if the data migrates to Unicode script — revisit only as part of the Wave 3 normalization, not before.
- **Writing a new transliteration library.** Reuse the org transcoder ([SHARED_CODE.md](https://github.com/sanskrit-lexicon/SHARED_CODE.md)); do not reinvent one.
